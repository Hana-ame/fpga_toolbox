# 功能增强 · Agent 友好的波形诊断工具 `diagnose_waveform`（工具 17 → 18）

## 背景

仿真失败时 Agent 通常只有一段日志和一份波形文件。日志会说「第 3 笔事务 FAIL」，
但不会说**为什么**。传统做法是人打开 GTKWave，用鼠标拖时间轴、点信号、看哪一拍
变 X —— 这正是文本 Agent 做不到的事。

本工具把 VCD 波形压缩成**面向文本的结论**，让 Agent 直接拿到可操作的诊断。

## 实现（`fpga_toolbox/waveform_diag.py`，零外部依赖）

三个真实能力：

| 能力 | 输出 | 价值 |
|---|---|---|
| **X/Z 传播点** | 首个未知值出现的信号 + 时刻 + 位宽 | X 是仿真失败最常见根因（未复位寄存器、未连接端口、x 污染组合逻辑），从最早出现的那条往驱动源追溯通常就是根因 |
| **握手死锁窗口** | VALID 拉高后 READY 从未拉高的信号对 + 起始时刻 | 日志只会说「第 3 笔事务超时」，波形能直接指出「TVALID 从 t=30 一直拉高到仿真结束，TREADY 从未拉高」—— 指向 DUT 流控实现 |
| **恒定信号** | 整个窗口从未翻转的信号 | 疑似常量 / 未驱动 / 被 optimize 掉 |

设计取舍（刻意不做的事）：

- **不解析 FST**。FST 是压缩二进制格式，需要自定义位打包解码，且语义必须转回
  VCD 才有意义。只支持 VCD（文本格式），这已覆盖默认输出（`run_sim` 的
  `waveform_format` 默认 `vcd`）。遇到 FST/LXT2 给出可操作错误（改用 VCD 或用
  `fst2vcd` 转换），而不是抛解码异常。
- **不做图形渲染**。目标是「结论」，不是「图」。
- **不整份加载到内存**。VCD 可能几百 MB，逐行流式解析。

## 首次实现踩到的两个真实缺陷

1. **向量格式匹配顺序**：必须**先**试向量格式 `b<num> <id>`。单比特正则
   `^([01xzXZ])(\S+)$` 会把 `bx #` 误吞成「值=`b`、id=`#`」（`b` 是合法单比特值），
   于是那条 8 位向量的 X 根本不会被识别 —— 实测 X 检测返回 0 条（假阴性）。
2. **READY 前缀归一**：`_ready_of()` 除了裸名（`bvalid -> bready`）外，还要剥掉
   `s_axi_` / `m_axi_` / `s_axis_` 前缀。这些是**单个标识符**里的下划线前缀，
   `split(".")` 归一后仍是 `S_AXI_BVALID`，直接查表查不到。同一缺陷此前在
   `tb_linter.py` 里也踩过（把 `while (!(s_axi_bvalid && m_axi_bready))` 误判 R3），
   本轮一并修复。

## 注册与验证

- 注册为第 **18** 个原子工具，纳入 Layer 1 双射与 MCP `tools/list`；
- `docs/USER_MANUAL.md` 工具表补第 18 行；
- `tests/test_waveform_diag.py` 6 个用例：X 传播、死锁检测、**健康握手不误报**、
  FST 拒绝、空/不存在路径结构化错误。

| 场景 | 结果 |
|---|---|
| 带 X 污染的 VCD | `X count=1`，首个 X 在 `tb.data` t=0（8 位向量） |
| 握手死锁（tvalid 拉高、tready 恒低） | `deadlock count=1`，`valid_high_since=30` |
| 健康握手（tready 会拉高） | `deadlock count=0`（无假阳性） |
| FST 文件 | 结构化错误 + 指引改用 VCD |
| 六层门禁 | **6/6**，Layer 4 `214/214` 函数 / 38 模块 |
