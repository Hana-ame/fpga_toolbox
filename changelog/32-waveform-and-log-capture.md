# Changelog — 抓波形与完整日志：功能缺失 + 4 个「说抓到了其实没有」的缺陷

需求是「抓波形和 log」。先确认现状：整个工具箱**完全没有**波形与日志持久化——
`grep -rn 'vcd|fst|dumpfile|dumpvars|--trace'` 在 `fpga_toolbox/` 和所有 sim 脚本里
零命中；`run_sim` 只在返回值里放 `stdout_tail`（4000 字符）和 `stderr_tail`
（2000 字符），**完整日志直接丢弃**。

实测一份 27923 字符的日志，返回值里只剩 4000 字符尾部——开头被丢掉，而第一条
断言失败附近的行往往正好落在被丢掉的部分。调试时等于没有日志。

## 新增能力

### 1. 完整日志落盘

`run_sim(log_dir=...)` 把**完整** stdout+stderr 写成 `sim_<suite>.log`：

```json
"log": {"path": "/tmp/out/sim_apb.log", "size_bytes": 1619, "lines": 16,
        "truncated_in_response": false}
```

`truncated_in_response` 明示「返回值里的 tail 是不是被截断了」——需要全文就去
读那个文件，而不是以为拿到的是全部。

### 2. 波形抓取

`run_sim(waveform=True)` 置 `WAVE=1`，生成的 sim 脚本据此给 verilator 加
`--trace`（`waveform_format=fst` 时为 `--trace-fst`）。TB 侧的 `$dumpfile` /
`$dumpvars` 由 `+WAVE` plusarg 控制：

```verilog
if ($test$plusargs("WAVE")) begin
  if ($value$plusargs("WAVE_FILE=%s", wave_path)) begin
    $dumpfile(wave_path);
  end else begin
    $dumpfile("wave.vcd");
  end
  $dumpvars(0, tb_apb_slave_apb);
end
```

产物被收集成结构化列表（`kind` / `size_bytes` / `empty` / `path`），支持
VCD / FST / LXT2 / WLF / SHM。

实测：APB 波形 2581 字节、**30 个信号声明、78 个时间点**；AXI4 波形 6199 字节、
78 个信号、114 个时间点。7 个协议模板全部注入成功（7/7）。

## 缺陷 A — `$value$plusargs` 目标变量未声明，直接编译失败

第一版只注入了这段，忘了声明 `wave_path`：

```
%Error: tb_apb_slave_apb.sv:46:43: Can't find definition of variable: 'wave_path'
   46 |       if ($value$plusargs("WAVE_FILE=%s", wave_path)) begin
%Error: Exiting due to 1 error(s)
```

纯看代码看不出来，**真的编译一次**才暴露。修复：在 `endmodule` 前声明
`string wave_path;`，并加回归断言 `"string wave_path" in src`。

## 缺陷 B — `require_waveform=true` + `waveform=false` 静默通过

语义矛盾：要求「必须有波形」却不开 `--trace`，那么永远不可能有波形。旧实现
直接放行返回 `ok=True`。修复：显式报 `E024`：

```
require_waveform=true needs waveform=true: without --trace verilator silently
ignores $dumpvars, so no waveform can ever be produced.
```

## 缺陷 C — 旧波形冒充本次结果

更隐蔽的一个。只判断「这个目录里有没有 `.vcd`」是不够的：

```python
# 旧逻辑：仅当 waveform=True 才做新鲜度过滤
if waveform:
    waves = [w for w in waves if mtime(w) >= started_at - 1.0]
```

两个问题叠加：

1. `waveform=False` 时**完全不过滤**，磁盘上的旧波形会出现在返回的 `files` 列表里，
   被调用方读成「这次产出了波形」（实测复现：`waveform=false` + 旧 `.vcd` 时
   `files` 非空）；
2. 即使 `waveform=True`，`mtime >= started_at` 也不可靠——上一次运行刚产生的文件、
   或文件系统时间精度粗，都会被算进来。

修复：**无条件**在运行前对已有波形拍快照 `(size, mtime)`，运行后只认新增或
发生变化（`size`/`mtime` 都变）的文件。实测：目录里有 `wave_stale.vcd`、
脚本不产生波形时，`files=[]` 且报 `E024`。

## 缺陷 D — FST 缺 lz4 头文件时产出假格式文件

本机 Verilator 5.054 自建时只装了 `liblz4.so.1`（运行时库），**没有 `lz4.h`**：

```
verilated_fst_c.cpp: fatal error: lz4.h: No such file or directory
```

危险之处：若 `obj_*` 里已有 VCD 二进制，脚本会**复用**它（构建缓存的
`.wave_enabled` 标记只记录「有没有开波形」，不区分格式），于是产出一个
**后缀 `.fst`、内容其实是 VCD** 的文件。实测文件头就是
`$version Generated by VerilatedVcd` —— 只看扩展名完全无法发现。

修复两处：

1. 加 `_fst_available()`：用一次极小规模编译探测 `--trace-fst` 是否可构建，
   不可用时显式报 `E025` 并给出可执行建议（装 `liblz4-dev`，或改用 vcd）；
2. 缓存标记记录格式（`.wave_enabled` 内容写格式），格式变化时强制重建。

```
$ run_sim --waveform --waveform-format fst
ok: False
diagnostics: E025  verilator --trace-fst needs the lz4 development headers (lz4.h)
                   at build time. Install liblz4-dev / lz4-devel, or use
                   waveform_format='vcd'.
```

## 新增诊断码

| 码 | 含义 |
|---|---|
| `E024` | 要求波形却无有效产物（缺 `--trace` 时 verilator 静默忽略 `$dumpvars`）；或 `require_waveform` 与 `waveform` 矛盾 |
| `E025` | `waveform_format=fst` 但环境缺 lz4 开发头文件，无法构建 `--trace-fst` |

## 自审计 A12

新增 `A12_WAVEFORM_LOG_ARTIFACT_GUARD`，同时验证三件事：

```
A12_WAVEFORM_LOG_ARTIFACT_GUARD
  contradictory ok=False codes=['E024']
  stale ok=False files=0 codes=['E024']
  log_saved=True
```

反向验证：把 `run_sim` 里两道波形断言都换成 `if False`，A12 立刻 FAIL，
整体 **12/12 → 11/12**，并指出具体失效项（`contradictory ok=True codes=[]`）。
