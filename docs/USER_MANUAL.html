1. 系统设计原理与四层确定性架构

传统验证脚本最大的隐患是“静默假通过”——少跑一个套件、拿错旧二进制、网表黑盒位宽冲突或测试台只打印不断言，退出码却依然是 0。fpga_toolbox 把整个流程拆成 13 个单一职责工具，每个环节都内置机器可判的硬守卫，所有输出统一封装为 {"ok", "tool", "data", "diagnostics", "error"}。

双后端 AST 解析原理

sv_parser.py 优先调用 slang 12.2 获取完整编译级 AST（自动解析跨文件包导入与参数求值）；若环境无 slang，显式降级内置解析器并附带 W013 诊断。内置解析器同时兼容 ANSI 与 Verilog-1995 非 ANSI 模块（含依赖参数求值）。

双路径 TB 生成原理

契约路径把 YAML/JSON 编译为 CompiledUnitIR，为双侧 AXI4-Lite↔APB 桥自动生成 *_apb_slave_model.sv + Makefile + SVA 心跳；多协议路径直接由 AST 生成显式端口连接、位宽缩放且匹配高/低有效复位极性的 SV 测试台。

零假通过守卫原理

从 lint_tb 的静态 C/R/S 规则，到 run_sim 的套件身份与波形时间戳校验，再到 result_normalizer 的截断拦截与 run_mutation 的真实 RTL 故障杀伤，每一层都用确定性断言替代人工目测。

4. 本轮对抗测试抓出的 5 个真实代码 Bug 与修复说明

在把函数覆盖率拉到 133/133（100.0%） 的过程中，我们刻意针对边界场景构造了对抗用例，直接在现有代码里抓出并修复了 5 个真实缺陷（全部已补进 tests/test_full_coverage.py 防止回归）。

BUG 1 · 高危假通过 · eda_campaign.py

多时钟组 DC/PT QoR 只看第一组

parse_dc_pt_qor 原先只取第一处 Critical Path Slack。当 pcs_clk 为 0.00 而第二组 cfg_clk 违例 −0.25 ns / 14 条 时，竟返回 timing_clean=True。已改为跨全部分组聚合 min(WNS)、sum(TNS) 与 sum(violating_paths)。

BUG 2 · 复位极性反接 · protocol_tb_emitter.py

高有效复位 DUT 被永久按在复位态

7 类协议测试台模板原先全部写死低有效复位（0 → 1），忽略 extract_interfaces 已检测出的 active_low=False。遇到 input logic reset 的 DUT 会一直保持 reset=1。现已按实际复位极性自动翻转初始化与释放电平。

BUG 3 · 漏删黑盒 · eda_campaign.py

PT 网表清理漏掉 Verilog 转义标识符

DC 综合网表常见带斜杠的转义实例名（如 RDBUS \u_rd/0 (.o_d(q));），旧正则 [A-Za-z0-9_\$]+ 无法匹配 / 导致 removed_instances=0。已扩展为 (?:\\\S+|[A-Za-z0-9_\$]+) 完整清理。

BUG 4 · 位宽塌缩 · core/sv_parser.py

非 ANSI 模块依赖型 localparam 求值失败

Verilog-1995 模块中 parameter W=8; localparam H=W-1; input [H:0] a; 在 _parse_non_ansi 中未把已有 params 传入 _parse_params，导致 H 未求值、端口位宽错误塌缩为 1。已透传 seed=params 彻底修复。

BUG 5 · 渲染截断 · visual_renderer.py

SV 字符串里的 // 被误切为注释

_highlight_sv 原先直接 raw.split("//", 1)，遇到 $display("http://...") 时把半句字符串错染成注释。已改为带引号/转义状态的逐字符扫描，仅切分字符串外的真实行注释。
