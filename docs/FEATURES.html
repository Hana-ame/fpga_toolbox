功能手册

fpga_toolbox 功能手册

13 个原子工具、统一信封、37 个诊断码 —— 面向 AI Agent 与人类工程师的 FPGA/ASIC 验证工具箱

面向 AI Agent 与人类工程师的 FPGA/ASIC 验证工具箱。13 个原子工具，统一信封、 统一错误码、可直接从 MCP / CLI / Python 三处调用。

1. 它解决什么问题

FPGA 验证里最常见的失败不是"断言失败"，而是看起来通过了：

症状真实原因本工具箱的对策
CI 全绿，上板挂测试台只 $display("DONE")，没有任何判定lint_tb 的 S1/S2/S3 规则检出静默通过
报告写 "0 errors"仿真崩在第 1 条断言，日志残缺normalize_sim_result 校验产物完整性
"覆盖率 100%"覆盖率数据来自旧二进制run_sim 逐套件身份核对 + 版本守卫
"已清理网表"清理器没匹配到实例，原样输出clean_pt_netlist 产物自检（E051）
"依赖完整"例化了仓库外的模块，静默丢失index_repo 的 W102 + closure_is_complete

工具箱的核心主张：任何"通过"都必须能被反问"你凭什么说它通过了"。 每个工具除了给出结果，还要给出让结果可被质疑的证据——诊断码、产物校验、 自审计项。

2. 架构

text
                    ┌─────────────────────────────┐
   MCP / CLI / Python ──▶│  call_tool(name, params)    │
                    │  ① 未知参数名校验            │
                    │  ② required 校验             │
                    │  ③ type 校验                 │
                    │  ④ enum 校验                 │
                    └──────────────┬──────────────┘
                                   ▼
                    ┌─────────────────────────────┐
                    │  13 个原子工具（纯函数）      │
                    └──────────────┬──────────────┘
                                   ▼
                    ┌─────────────────────────────┐
                    │  ToolResult 统一信封         │
                    │  {ok, tool, data,           │
                    │   diagnostics, error}       │
                    └─────────────────────────────┘

统一信封意味着调用方只需写一次错误处理，13 个工具全部适用：

python
r = call_tool("index_repo", {"project_root": "."})
if not r["ok"]:
    print(r["error"])                       # 人类可读的一句话
    for d in r["diagnostics"]:              # 结构化诊断
        print(d["code"], d["path"], d["message"])

3. 工具分组

3.1 仓库理解（1–3）

index_repo — 仓库索引

解析 RTL 仓库，得到模块、例化关系、头文件归属。

shell
python3 -m fpga_toolbox index_repo --project-root examples/multi_bus_ref
json
{
  "ok": true,
  "data": {
    "total_rtl_files": 36,
    "modules": {
      "apb_slave": {
        "file_path": "apb_slave.sv",
        "instantiated_modules": [],
        "unresolved_instantiations": [],
        "includes": []
      }
    },
    "unresolved_instantiations": {}
  }
}

关键能力：unresolved_instantiations 与 W102。

当 RTL 例化了一个仓库里没有定义的模块（厂商 IP、加密 IP、尚未克隆的子模块）， 本工具不会静默忽略：

json
{
  "unresolved_instantiations": {"soc_top": ["vendor_ddr_phy", "secure_boot_rom"]},
  "diagnostics": [
    {"severity": "WARNING", "code": "W102", "path": "soc_top",
     "message": "Instantiation of module 'vendor_ddr_phy' has no definition in this repo; ..."}
  ]
}

为什么重要：这类模块在真实项目里极常见。静默丢弃会让依赖闭包"看起来完整"， 沙箱缺文件、综合缺模块，而所有中间步骤都报成功。

resolve_deps — 依赖闭包

BFS 计算目标模块的传递依赖。带环不死循环，并透传上游的未解析例化信息。

shell
python3 -m fpga_toolbox resolve_deps --target-module axi_apb_bridge --project-root examples/axi_apb_ref
json
{
  "ok": true,
  "data": {
    "dependency_closure": ["axi_apb_bridge", "apb_slave_regs"],
    "dependency_edges": [{"from": "axi_apb_bridge", "to": "apb_slave_regs"}],
    "rtl_files": ["axi/sv/axi_apb_bridge_sv.sv", "..."],
    "unresolved_instantiations": {},
    "closure_is_complete": true
  }
}

closure_is_complete: false 是给调用方的单点信号：这份文件清单不完整， 别直接拿去建沙箱。

copy_sandbox — 隔离沙箱

带 SHA-256 校验的复制，且拒绝越界。

shell
python3 -m fpga_toolbox copy_sandbox \
  --project-root examples/axi_apb_ref \
  --relative-files axi/axi_apb_bridge.sv axi/apb_slave_regs.sv \
  --sandbox-dir /tmp/sandbox

安全边界（都有测试锁定）：

行为结果
沙箱 = 项目根拒绝
沙箱是项目根的祖先拒绝
清理非空目录但无 .fpga_sandbox 标记拒绝（除非 force=true）
相对路径含 .. 或绝对路径拒绝
项目内符号链接指向项目外拒绝（解析真实路径后校验）

最后一条是实测发现的：rtl/link.sv -> /outside/creds.txt 这样的符号链接 曾能把项目外文件内容搬进沙箱。项目内部的符号链接（解析后仍在根内）正常放行。

3.2 接口与契约（4–6）

extract_interfaces — 多协议接口识别

从 RTL 识别 11 种接口，支持内置解析器与可选 slang AST 后端。

shell
python3 -m fpga_toolbox extract_interfaces --rtl-file examples/multi_bus_ref/pcie_tlp_ep.sv
json
{
  "ok": true,
  "data": {
    "modules": [{
      "module_name": "pcie_tlp_ep",
      "clock": {"port": "clk", "freq_mhz": 100.0},
      "reset": {"port": "rst_n", "active_low": true, "sync": true},
      "interfaces": [{
        "protocol": "pcie",
        "role": "endpoint",
        "pcie_gen": 4,
        "pcie_lanes": 4,
        "port_map": {"tx_valid": "pcie_tx_tvalid", "...": "..."}
      }]

支持的协议：axi4_lite · axi4（Full）· axi4_stream · apb · ahb_lite · ddr3 · ddr4 · hbm · pcie · spi · ethernet，外加 SV interface/modport。

时钟/复位识别支持常见命名：clk/aclk/pclk/hclk、rst_n/aresetn/hresetn/presetn。

validate_contract — 契约校验

校验 YAML/JSON 边界契约与寄存器位域规则。

shell
python3 -m fpga_toolbox validate_contract --spec-path /tmp/bad_spec.yaml
json
{
  "ok": false,
  "error": "Semantic validation failed.",
  "diagnostics": [
    {"severity": "ERROR", "code": "E001",
     "path": "boundary.axi4_lite.port_map.awvalid",
     "message": "Missing required 'awvalid'."}
  ]
}

诊断码（校验类）：

码含义
E000缺 boundary / test_plan 段
E001必需端口未映射
E002data_width 不是 32/64
E011契约里的端口在 RTL 中不存在
E012端口方向与预期不符
E013位域重叠
E014位域超宽
E015位域 bits 顺序写反（hi<lo）

E015 值得一提：bits: "7:0" 写成 "0:7" 时，旧实现报 E014 越界， 误导用户去改宽度。现在专门报"顺序反了"。

emit_testbench — 两条路径

路径 A：契约驱动（生成 AXI4-Lite wrapper + SVA + bind + cocotb）

shell
python3 -m fpga_toolbox emit_testbench \
  --spec-path contract.yaml --out-dir /tmp/tb --rtl-file dut.sv

产出 4 个工件：unit_isolation_wrapper / sva_protocol_checker / in_situ_bind_file / cocotb_testbench。若 DUT 是双侧桥（AXI4-Lite + APB master）， 额外生成 apb_slave_model 并报 dual_side: true。

路径 B：多协议直出（从 RTL 直接生成自检 SV TB）

shell
python3 -m fpga_toolbox emit_testbench \
  --rtl-file examples/multi_bus_ref/apb_slave.sv \
  --out-dir /tmp/tb_apb --protocol apb
json
{"ok": true, "data": {"protocol": "apb", "suites": ["apb"],
 "artifacts": {"sv_testbench": "...", "sim_script": "..."}}}

7 种协议可用：apb / axi4 / ahb_lite / ddr3 / ddr4 / hbm / pcie （PCIe 自动展开 Gen3·4·5 × x1·x4·x16 共 9 套件）。

生成的 TB 自带 Verilator 运行脚本，跑起来是这样的：

shell
$ bash /tmp/tb_apb/run_apb_slave_apb.sh
== sim: apb (top=tb_apb_slave_apb) ==
[CHECK] id=APB_001 | proto=APB | cat=reset_read | tx=RD addr=0x0000 | exp=0x12345678 | got=0x12345678 | status=PASS
[CHECK] id=APB_002 | proto=APB | cat=pstrb_write | tx=WR addr=0x0000 wdata=0xaa00bb00 strb=0xa | status=PASS
...
PASS: apb all 8 checks passed

生成前的三道闸门（每个都是实测缺陷的产物）：

  1. 端口存在性 — DUT 缺模板要连的端口时 fail-fast（否则生成 .pstrb(pstrb)

连到不存在的端口，Verilator 报 PINNOTFOUND）；

  1. 端口方向 — DUT 把 pready 写成 input 时 fail-fast。这个比编译失败更危险：

方向错不会编译失败，但 TB 的 while (!pready) 会永久挂起，CI 表现为超时；

  1. 端口位宽 — 窄总线上测试向量按 dw 缩放，避免 8'h12345678 被静默截断。

3.3 结果归一化与可视化（7–8）

normalize_sim_result — 三源合一

把 cocotb XML/JSON、SVA 日志、Verilator 多套件日志归一化成统一报告。

shell
python3 -m fpga_toolbox normalize_sim_result \
  --module-name apb_slave --verilator-log-path /tmp/sim.log --expected-suites apb dual
json
{
  "ok": true,
  "data": {
    "overall_status": "PASS",
    "checks": [{"rule_id": "APB_001", "category": "reset_read", "status": "PASS", "detail": "..."}],
    "summary": {"total": 8, "passed": 8, "failed": 0, "skipped": 0, "pass_rate": 1.0}
  }
}

三个输入源都有完整性信号——这是本工具最重要的设计：

输入源完整性信号缺信号时的行为
cocotb JSONcompleted: truecompleted=false → COCOTB_INCOMPLETE FAIL
SVA 日志[SVA:HBEAT] 心跳有心跳无违例 → PASS；无心跳无违例 → NO_RESULTS
Verilator 日志PASS:/FAIL: 汇总行计数启动 N 套件需 ≥N 条汇总，不足 → VERILATOR_NO_SUMMARY FAIL

为什么必须有这层：仿真日志天然容易被截断（被杀、超时、崩溃）。只统计 "我看到了什么"而不判断"我是否看完"，就会把残缺产物当成完整结论。

SVA 的特殊之处：断言通过时零输出，所以加了周期性心跳 [SVA:HBEAT] rule=P_000 monitored_cycles=100 status=ACTIVE， 让"全通过"与"引擎根本没跑"可区分。

render_visual_report — SVG + HTML 看板

shell
python3 -m fpga_toolbox render_visual_report \
  --report-json /tmp/report.json --dep-graph-json /tmp/graph.json \
  --ifaces-json /tmp/ifaces.json --out-html-path /tmp/report.html

产出 SVG 依赖拓扑 + HTML 规则审计看板，内置 HTML 标签平衡与行数一致性自检 （consistency_ok）。看板包含 SV 语法高亮、方向/位宽徽章、mutation 矩阵。

3.4 反踩坑与执行（9–11）

lint_tb — 静态反踩坑

shell
python3 -m fpga_toolbox lint_tb --target-path /tmp/bad_tb.sv
json
{
  "ok": false,
  "data": {"error_count": 2, "warning_count": 0,
    "findings": [
      {"severity": "ERROR", "code": "C1",
       "message": "Blocking interface drive immediately after @(posedge) ..."}
    ]}
}

三组规则（S 组对 .sh/.py 与 .sv 都生效）：

组码抓什么
时钟竞争C1 C2@(posedge) 后立即用阻塞赋值驱动 interface 信号
握手死锁R1–R4valid 撤回过早、ready 无限等待、响应超时
静默通过S1 S2 S3 S4常量返回的 stub 函数、SKIP 后 exit 0、只数 PASS 行数、SV 测试台只 $display 无任何判定

S4 是 SV 测试台的静默通过检测：文件里有 $display 却没有任何 assert / $error / $fatal / 自研 check_* 任务，说明它只在汇报、 从不表达失败——这样的仿真必然"通过"。判定前会剥掉注释，并对带真实判定的 TB 保持零误报（examples/multi_bus_ref 的 18 个 TB 全部干净）。

C1/C2 覆盖常见接口实例命名（*_if / *_bus / axi / apb / s_axi / m_axi / u_axi），且只在 @(posedge) 上下文触发以控制误报。

run_sim — 仿真封装（含波形与完整日志）

shell
python3 -m fpga_toolbox run_sim \
  --sim-script examples/multi_bus_ref/sim.sh --suite apb \
  --log-dir /tmp/out --waveform --require-waveform
json
{
  "ok": true,
  "data": {
    "returncode": 0,
    "elapsed_sec": 7.871,
    "log": {
      "path": "/tmp/out/sim_apb.log",
      "size_bytes": 1619,
      "lines": 16,
      "truncated_in_response": false
    },
    "waveform": {
      "requested": true,
      "format": "vcd",
      "total_bytes": 2581,
      "files": [{"kind": "VCD", "size_bytes": 2581, "empty": false, "path": ".../wave_apb.vcd"}]
    }
  }
}

抓 log：log_dir 把完整 stdout+stderr 落盘为 sim_<suite>.log。 不传时返回值只有 4000/2000 字符的尾部——长日志的开头会被丢弃，事后无法 回溯第一条断言失败附近的上下文（实测 27923 字符的日志，返回值里只有 4000）。

抓波形：waveform=true 会置 WAVE=1，让生成的 sim 脚本给 verilator 加 --trace（waveform_format=fst 时用 --trace-fst）。TB 里的 $dumpfile/$dumpvars 由 +WAVE plusarg 控制，产物落在脚本目录或 log_dir。

波形与日志的护栏：

码触发条件为什么需要
E020Verilator 版本 < 5.040旧版本跨文件 virtual interface 有缺陷
E021require_slang=true 但 slang 缺失显式要求就要显式失败
E022仿真退出码非 0—
E023套件静默跳过逐套件身份核对
E024要求波形但没产出非空波形 / require_waveform 与 waveform 矛盾Verilator 缺 --trace 时静默忽略 $dumpvars，仿真 PASS 但波形不存在
E025waveform_format=fst 但环境缺 lz4 开发头文件否则会产出「后缀 .fst、内容是 VCD」的假文件

require_waveform 的判定不只看文件是否存在：它会与运行前的波形快照 比对 (size, mtime)，只认本次新增或变化的文件。否则上一次运行遗留的 .vcd 会被当成本次证据，让「其实没抓到」也能通过。

run_mutation — 变异测试

shell
python3 -m fpga_toolbox run_mutation \
  --workdir /tmp/mut --mutation-spec /tmp/muts.json --test-cmd "python3 -m pytest -q"

在 try/finally 里保证原文件还原，并拦截残留变异（E030）。

json
{"ok": true, "data": {"mutation_score": 100.0, "killed": 4, "survived": 0}}

3.5 工程辅助（12–13）

clean_pt_netlist — PrimeTime 网表清理

DC 导出的网表里常有未解析的参数化黑盒（RDBUS/CLKCROSSBUS/CLKCROSSDFF）， 导致 PrimeTime link_design 失败。

shell
python3 -m fpga_toolbox clean_pt_netlist --in-verilog nl.v --out-verilog nl_clean.v
json
{"ok": true, "data": {"removed_instances": 2, "tied_off_nets": ["dout[15:0]", "dout[16]"]}}

输出示例：

systemverilog
module soc(clk, dout);
  input clk;
  output [31:0] dout;
// [fpga_toolbox:pt_clean] removed unresolved parameterized blackbox instance
// [fpga_toolbox:pt_clean] removed unresolved parameterized blackbox instance
  assign dout[15:0] = 1'b0;
  assign dout[16] = 1'b0;
endmodule

产物自检：清理后若输出里仍有黑盒实例（实例语法没被匹配到，如缺分号）， 返回 E051 而不是静默报成功。

audit_harness — 故障注入自审计

给护栏本身做故障注入，证明它们出错时不会静默通过。

shell
python3 -m fpga_toolbox audit_harness
json
{
  "ok": true,
  "data": {
    "total": 10, "passed": 10, "failed": 0,
    "checks": [
      {"id": "A1_LINT_FAULT_CATCH", "passed": true, "detail": "ok=False codes=['C1', 'R2']"},
      {"id": "A2_MUTATION_RESIDUAL_GUARD", "passed": true, "detail": "ok=False codes=['E030']"},
      ...
      {"id": "A10_PT_NETLIST_RESIDUAL_GUARD", "passed": true, "detail": "ok=False codes=['E051']"}
    ]
  }
}
项验证什么
A1lint_tb 能抓到时钟竞争与握手缺陷
A2run_mutation 拒绝残留变异（E030）
A3normalize_sim_result 拒绝垃圾 JSON，不静默 PASS
A4copy_sandbox 拒绝以项目根为沙箱
A5/A6套件身份核对能解析真实日志、套件齐时不假报警
A7Verilator 版本守卫（E020）生效
A8emit_testbench 缺 boundary 时 fail-fast
A9slang 回退对调用方可见（W013）
A10clean_pt_netlist 清理残留时报 E051

码含义

E010out_of_scope_ports 的输入端口缺 tie_off
E011契约端口在 RTL 中不存在
E012端口方向不符
E013位域重叠
E014位域超宽
E015位域 bits 顺序写反（hi<lo）

运行时类

码工具含义

E021run_sim要求 slang 但缺失
E022run_sim仿真退出码非 0
E023run_sim套件静默跳过
E024run_sim要求波形却无有效产物（缺 --trace 时 verilator 静默忽略 $dumpvars）；或 require_waveform 与 waveform 矛盾

警告类

码工具含义

W011extract_interfaces未检测到复位，用默认值

W101copy_sandbox被 include 的文件未进沙箱

6. 边界与已知限制

诚实记录，避免误用：

  • emit_testbench 契约路径只生成 AXI4-Lite wrapper。纯 APB 设备会明确拒绝

（Spec has no AXI4-Lite boundary），不会生成坏产物。

  • 多协议 TB 是定宽模型：ddr4 模板固定 64 位数据总线（地址高 3 位编码命令，

与位宽强耦合）；ddr3 的地址/数据位宽可随接口推断。DUT 位宽严重不符时会 被端口校验拦下，但不会自动适配全部协议变体。

  • eda_campaign 是库模块（不注册为工具），面向 Synopsys VCS/DC/PT 的论文

复跑流程，需要远端环境，本地只做日志解析与网表处理。

  • copy_sandbox 不解析 include 依赖，只复制调用方显式列出的文件；

缺依赖时通过 include_warnings（W101）提醒，不自动补全。

  • Verilator < 5.040 的跨文件 virtual interface 有缺陷，run_sim 会拒绝。
